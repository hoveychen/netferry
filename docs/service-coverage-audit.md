# 服务范围识别覆盖率审计

用本机两份分组的 `knownHosts` 和规则键做只读计数；未输出具体主机或规则值。

| 分组 | 目标总数 | 纯 IP | 域名及规则模式 |
| --- | ---: | ---: | ---: |
| 较大分组 | 1002 | 494 | 508 |
| 较小分组 | 106 | 47 | 59 |

第一版固定目录在较大分组识别 85 个目标、形成 7 个候选服务。纯 IP 占约一半：共享 CDN、DNS 缓存和连接复用使 IP 无法可靠反推服务；不能把 IP 自动归到品牌范围，否则可能误路由其他应用。

扩充后的客户端用 `tldts` 判别 IP，较大分组识别为 498 个 IP；这与上表 Python 标准库严格解析的 494 个略有差异。新目录在较大分组识别 225 个目标、形成 26 个候选服务；域名站点为 289 个。较小分组识别 41 个目标、形成 11 个候选服务，域名站点为 32 个。这些是同一份历史数据的只读测量，用户没有确认任何新规则。

固定版本 V2Fly 目录中的未用清单有实际增量。匿名按清单计数，Lark、腾讯、Stripe、Meta/WhatsApp、广告跟踪、金融、娱乐和社交等覆盖当前未识别域名。扩充目录时保留精确主机与域名后缀语义，并正确处理 `include:foo @ads` 这类标签选择；分类重叠时先展示具体服务，再展示宽类别。新增候选仍须用户预览确认才会成为规则。

客户端把纯 IP 收入单独折叠入口，避免约 494 个地址在“未归组站点”里逐项占位；搜索和展开仍可访问完整地址。

再次用同一份本机历史分组做只读统计，按客户端的 `normalizeDomain` 和精确主机优先、最长域名后缀优先的识别逻辑计算。没有输出或修改主机数据。

较大分组的新增命中来自 Yahoo 7、加密货币类别 6、Cloudflare 4、Udemy 4、隐私同意管理类别 3、Medium 3、Intercom 3、hCaptcha 3、Snap 2。较小分组新增来自加密货币类别 6、Cursor 2、Intercom 1。目录仍固定在同一 V2Fly 提交，候选仍须预览并保存才生效。

上游的地理区域、公司和 CDN 大类还能命中更多未识别目标，但其共同语义不足以形成可靠的服务路由范围，本轮没有纳入。
